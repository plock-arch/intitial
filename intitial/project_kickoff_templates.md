## Usage Guidelines

### When to Use Each Template

**Project Charter** → Formal project initiation, getting executive approval  
**Amazon 6-Pager** → Strategic decisions, major initiatives requiring executive alignment  
**Google Design Doc** → Technical design before coding, when multiple approaches exist  
**ADR** → Documenting architectural decisions AFTER they're made  
**DIBB** → Product strategy, prioritization decisions  
**Technical Design Doc** → Core Platform projects bridging business and tech  
**PR/FAQ** → New product/feature development, customer-centric planning  
**RFC** → Gathering feedback on proposals, collaborative decision-making  

### Template Selection Decision Tree

```
Is this a new project needing formal approval?
  → YES: Project Charter

Is this a strategic business decision needing executive buy-in?
  → YES: Amazon 6-Pager or PR/FAQ

Are you designing a technical solution with multiple options?
  → YES: Google Design Doc or RFC (for feedback)

Have you made an architectural decision that needs documentation?
  → YES: ADR

Are you prioritizing product bets/initiatives?
  → YES: DIBB Framework

Is this a Core Platform project needing business-technical bridge?
  → YES: Technical Design Document
```

## Customization for Core Platform (cURL Team)

When adapting these templates for your Core Characteristics, Core Returns, and Core Meta work:

1. **Always include**:
   - Impact on Lens interface/API contracts
   - Downstream frontend application effects
   - Data integrity considerations
   - Performance implications (calc times)
   - Links to GitHub issues and Figma designs

2. **Stakeholder mapping**:
   - Business stakeholders: Portfolio managers, analysts using the data
   - Technical stakeholders: Frontend teams, other Core Services teams
   - Platform stakeholders: DevOps, Security, Compliance

3. **Success metrics specific to Core Platform**:
   - API response times (P50, P95, P99)
   - Data accuracy/consistency
   - Calculation performance
   - User adoption of new features
   - Reduction in support tickets
